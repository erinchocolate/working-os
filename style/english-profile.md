# 主人的英语表达风格（规则化 · 常驻指针）

由「润色 收」维护。每条都是**能直接当 prompt 用的规则**，不是 diff 堆砌。
出英文（润色 / 分享英文稿）时，先读本文件并套用这些规则。

## 用词
- 优先最常见、最简单的词；能用日常词就不用更“高级”的词
- 用 `needs`，少用 `depends on`
- 不在原文没有形容词的地方加形容词（e.g. 不把 "note" 改成 "detailed note"）
- 不添加原文没有的情感性 / 客套性短语（e.g. "I really appreciate the transparency"）
- 技术问题复述时可以用 `caused issues for the app` 这类概括表达，不必总是保留非常具体的失败结果
- 在 Teams/Slack 短消息里，函数名、字段名这类技术词可以直接写普通文本，不主动加 Markdown backticks
- 介绍新文档类型/项目名时，少用插入语逗号；优先写成 `a new document type Checksheets (CCS) into Marvin` 这类顺口的直陈结构

## 句式 / 结构
- 短句、直陈句优先
- 短消息写成单段，不分段落
- 问候语 "Hi Name," 内嵌在段落起始，不单独成行
- 并列句前不加逗号（"candidates and please"，非 "candidates, and please"）
- 内部经验分享可以用 `Shared a lesson we learned:` 开头，直接进入主题

## 语气 / 直接度
- 直说意图，不软化；用 `we want to` / `I want to`，少用 `we'd like to` / `I would like to`
- 请求权限用直陈句；用 `Is it okay if...`，少用 `Would it be okay if...`
- 偏直接简洁；不升级原文的感激程度或情感热度
- 忠于原文语气，不主动添加温情修饰
