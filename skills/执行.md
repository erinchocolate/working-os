# skill: 执行 —— 基于共享 context + 真实代码仓库完成任务

**触发**：主人说「执行 <项目名> <需求>」「改代码」「实现这个任务」等。

**目的**：复用 `/opt/processes/context_platform` 中的共享项目 context，少走弯路；任务结束后把共享事实回写到 context repo，把个人认知沉淀到 working-os。

## 先读（重要：先读再动手）
1. 常驻指针：`assets/INDEX.md`（主人的通用方法/坑）。
2. `/opt/processes/context_platform/README.md` 和
   `/opt/processes/context_platform/AGENTS.md`。
3. 目标项目的共享 context，例如
   `/opt/processes/context_platform/projects/marvin/index.md`，再按 index 读取
   relevant design、decisions、known failure modes、workflows、feedback。
4. 真实代码仓库与表结构；共享 context 只给地图，代码从真实 repo 读取。

## 流程
1. 读完共享 context 和真实代码后，确认理解需求；有歧义先澄清。
2. 检查项目已知 failure modes：这个需求会不会撞上已知坑。
3. 在真实代码仓库中完成任务。
4. **副产品自动回写**：
   - 新项目事实 / 决策 / workflow / 坑 → 写入 `/opt/processes/context_platform` 对应项目或共享目录。
   - 写入 `context_platform` 的内容默认用英文；中文输入先翻译成英文。
   - 个人方法 / 反思 / 偏好 → 写入 `working-os` worklog；有可复用反思时同步 recurring。
5. **写执行 worklog**：任务结束时写
   `worklog/<日期>-<项目>-<简述>.md`，记录本次任务摘要。
6. **沉淀可复用认知**：如果本次任务产生可复用方法、坑、偏好或认知，在 worklog 中写 `## Reflections`，并按「收工」规则增量更新 `reviews/recurring.md`。
7. **轻提醒**：大任务完成后的最终回复里提醒主人可以用 `小结` 做 3 分钟记录；不要自动写小结，除非主人明确触发。

## worklog 格式
```
# <日期> · <项目> · <任务简述>

## Task
- 主人要完成什么。

## Context Used
- 读了哪些 context_platform context。
- 读了哪些代码路径。

## Changes / Output
- 改了什么或产出了什么方案。

## Shared Context Routed
- 哪些项目事实、决策、坑或 workflow 已写入 context_platform。

## Decisions / Pitfalls / Follow-ups
- 新决策、坑、待确认问题。

## Reflections
- type: 认知 / 坑 / 方法 / 偏好
  statement: 一句话认知
  evidence: 本次任务中的具体触发
  context: 所属项目/情境

## Review Inputs
- 复盘时应关注的 git roots、文件或对话线索。
```

## 原则
- 不把共享项目 context 写回 `working-os/projects`；`working-os/projects` 不再作为项目 context 容器。
- 只回写「代码说不出来的东西」：为什么这么做、踩了什么坑、定了什么，不复述代码。
- 执行结束的 worklog 是系统复盘的输入之一；有 `Reflections` 时必须同步进入 `reviews/recurring.md` 中间层。
- `小结` 是任务后的轻量捕获入口；执行 skill 不自动生成 daily 小结，只在大任务结束时轻提醒。
