# skill: 思考 —— 口述工作想法的思考陪练

**触发**：
- 「思考」+ 一段口述想法、困惑或判断。
- 「思考 <主题>」→ 围绕指定主题进行思考陪练。
- 「工作思考」「口述思考」→ 同上。

**目的**：承接还没有完全成形的工作想法。这个 skill 不是记录员，也不是素材卡生成器；它先做思考陪练：主人把想法倒出来后，agent 基于项目 context 和表达内容追问 2-3 个能挖深的问题。对话澄清后，再整理成当天 thinking worklog。

## 先读
1. `AGENTS.md`（确认目录边界、关键词优先级和 shared context 路由）。
2. 如果主题明显涉及某个项目，读 `/opt/processes/context_platform/projects/<project>/index.md` 和必要 shared context。
3. 当天 `worklog/<YYYY-MM-DD>-thinking.md`（如果存在），避免重复记录同一轮想法。
4. 如果用户要求把思考沉淀为素材，再读 `materials/index.md`；否则不要提前进入素材卡流程。

## 流程
1. 先听完整段口述，不要立刻写文件。
2. 用 2-4 句话复述你听到的核心判断和张力，确认自己理解的是哪一个问题。
3. 提 2-3 个追问，帮助主人把想法往下挖；默认不要问太多。
4. 追问方向可以包括：
   - 这个问题背后真正的判断是什么？
   - 有没有项目事实、用户反馈或系统限制支持/反驳这个判断？
   - 这个想法如果讲给别人听，最有价值的表达角度是什么？
   - 哪些点现在只是感觉，哪些已经有证据？
   - 它对下一步工作决策有什么影响？
5. 用户回应后，再追加到当天 `worklog/<YYYY-MM-DD>-thinking.md`。
6. 只标记 routing candidates；不要自动生成素材卡、不要自动晋升 `assets/mental-models.md`。
7. 如果出现明确项目事实、决策、用户反馈、workflow 或公司 context，标记 `shared_context_candidate: yes / maybe`；需要写入时走「摄取」或确认后路由到 `/opt/processes/context_platform`。

## thinking entry 格式

追加到 `worklog/<YYYY-MM-DD>-thinking.md`：

```md
## <HH:MM> · <short topic>

### Key Original Phrases
- "<short phrase from the user>"
- "<short phrase from the user>"

### Cleaned Thought
- ...

### Deeper Questions Explored
- Q:
  A:

### Current Judgment
- ...

### Evidence / Signals
- ...

### Open Questions
- ...

### Possible Next Step
- ...

### Routing Candidates
- recurring_candidate: yes / no / maybe
- material_candidate: yes / no / maybe
- possible_sharing_use:
- shared_context_candidate: yes / no / maybe
```

## routing 规则

| 信息类型 | 目标 |
|---|---|
| 还没成形的工作想法、困惑、判断、口述思考 | `worklog/<YYYY-MM-DD>-thinking.md` |
| 反复出现、能指导未来工作的认知 | 标记 `recurring_candidate`，由「收工/系统复盘」进入 `reviews/recurring.md` |
| 适合讲给别人听的解释、类比、故事、框架 | 标记 `material_candidate`，后续由「素材」转成 `materials/cards/` |
| 项目事实、决策、用户反馈、workflow、公司 context | 标记 `shared_context_candidate`，确认后进入 `/opt/processes/context_platform` |
| 少量、已验证、会改变主人工作方式的原则 | 只能由「系统复盘」晋升到 `assets/mental-models.md` |

## 原则

- 思考入口要有对话感：先帮主人看见自己的判断、假设和证据，再整理文字。
- thinking worklog 是过程材料，默认本地保存，不上传。
- 保留整理版 + 少量关键原话；不要逐字转写长段口述。
- 不把每次思考都变成素材卡。只有明显可迁移、可表达的部分，才标记为 `material_candidate`。
- 不把项目事实写进 working-os；共享 context 仍写入 `/opt/processes/context_platform`，并默认使用英文。
