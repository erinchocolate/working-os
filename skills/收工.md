# skill: 收工 —— 总结 session + 提炼认知 + 增量更新 recurring

**触发**：主人说「收工」「结束总结」「总结这次 session」「session digest」。

**目的**：把一次 AI 对话里值得带走的内容沉淀成 `worklog/`，同时做认知提炼并增量更新 `reviews/recurring.md`。这是日常唯一的"复盘"动作。

## 先读
1. `AGENTS.md`（确认目录边界）。
2. 若 session 明显属于某项目，读 `projects/<项目>/context.md` 和 `projects/<项目>/project.md`。
3. `reviews/recurring.md`（对照已有候选，判断本次认知是新增还是已有条目的新 evidence）。

## 流程
1. 回顾当前对话或任务，提取：主题、重要想法、决策、待办、可路由进项目 context 的内容。
2. 提炼本次 session 的认知（坑、方法、偏好、认知），写入 worklog 的 `## Reflections` 段。
3. 写 `worklog/<日期>-<简述>.md`。
4. **增量更新 `reviews/recurring.md`**：
   - 对每条 Reflection，和 recurring 中已有条目做语义匹配。
   - 匹配到 → 追加 instance（日期 + 原话），count +1，更新 last_seen 和 contexts。
   - 没匹配到 → 新增条目，count = 1，status = 候选。
5. 如果有项目事实、决策、坑已经足够明确，可按「摄取/执行」规则回写项目 context；若不确定，问主人。
6. 如果有 working-os 自身改进建议，记录为系统复盘候选，不静默改 skill。

## worklog 格式
```
# <日期> · Session · <简述>

## Topic
- 这次对话/任务围绕什么。

## Important Points
- 值得带走的重要点。

## Decisions
- 已形成的决定。

## Reflections
- type: 认知 / 坑 / 方法 / 偏好
  statement: 一句话认知
  evidence: 本次 session 中的具体触发
  context: 所属项目/情境

## To Route Into Context
- 应进入项目 context / skill 的候选。

## Follow-ups
- 后续要做的事。
```

## 原则
- worklog 可以保留中间思考的摘要，但不要把长对话逐字转存。
- Reflections 段是认知管道的原料；recurring.md 是中间层；assets/ 是终态。收工只负责前两层。
- 晋升到 assets/ 由「系统复盘」负责，收工时不做晋升判断。
