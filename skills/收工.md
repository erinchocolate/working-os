# skill: 收工 —— 日终整理 + 补漏 + 增量更新 recurring

**触发**：主人说「收工」「结束总结」「总结这次 session」「session digest」。

**目的**：日终整理当天工作材料：汇总 daily 小结、补遗漏、整理 follow-ups，并把值得复用的反思增量更新到 `reviews/recurring.md`。`小结` 是任务后的轻量捕获入口，`收工` 是一天结束时的整理和补漏。

## 先读
1. `AGENTS.md`（确认目录边界）。
2. 若 session 明显属于某项目，读对应的
   `/opt/processes/context_platform/projects/<project>/index.md`。
3. 当天 `worklog/<日期>-daily.md`（如果存在）。
4. `reviews/recurring.md`（对照已有候选，判断本次认知是新增还是已有条目的新 evidence）。

## 流程
1. 回顾当前对话、当天 daily 小结和任务结果，提取：主题、重要想法、决策、待办、可路由进共享 context 的内容。
2. 补充当天遗漏：如果有任务没有小结，追加到当天 daily worklog 或写入本次收工记录。
3. 整理 follow-ups：把散落的后续事项合并成清楚的行动列表。
4. 提炼当天值得复用的个人认知（坑、方法、偏好、认知），写入收工 worklog 的 `## Reflections` 段；不要强行从普通任务里制造反思。
5. 如果某条反思明显适合讲给别人听，标记 `sharing_material: yes` 或 `maybe`，并写一句 `possible_sharing_use`；不要把所有 reflection 自动转素材。
6. 写 `worklog/<日期>-<简述>.md`，或在当天 daily worklog 足够完整时追加 `## End-of-day Notes`。
7. **增量更新 `reviews/recurring.md`**：
   - 对每条 Reflection 或 daily `Reflection Candidate`，和 recurring 中已有条目做语义匹配。
   - 匹配到 → 追加 instance（日期 + 原话），count +1，更新 last_seen 和 contexts。
   - 没匹配到 → 新增条目，count = 1，status = 候选。
   - 如果有 `sharing_material` 和 `possible_sharing_use`，同步为 recurring 条目的可选字段。
8. 如果有项目事实、决策、坑、workflow 或 guideline 已经足够明确，按「摄取/执行」规则写入 `/opt/processes/context_platform`；若不确定，问主人。
9. 如果有 working-os 自身改进建议，记录为系统复盘候选，不静默改 skill。

## worklog 格式
```
# <日期> · Session · <简述>

## Topic
- 这次对话/任务围绕什么。

## Important Points
- 值得带走的重要点。

## Decisions
- 已形成的决定。

## Shared Context To Route
- 应进入 context_platform 的项目/公司 context 候选。

## Reflections
- type: 认知 / 坑 / 方法 / 偏好
  statement: 一句话认知
  evidence: 本次 session 中的具体触发
  context: 所属项目/情境
  sharing_material: yes / no / maybe
  possible_sharing_use:

## Follow-ups
- 后续要做的事。
```

## 原则
- worklog 可以保留中间思考的摘要，但不要把长对话逐字转存。
- Reflections 段是个人认知管道的原料；recurring.md 是中间层；`assets/mental-models.md` 是系统复盘后的行动原则层。收工只负责前两层。
- `小结` 已捕获的内容不要重复扩写；收工只做合并、补漏和必要的反思提炼。
- 适合表达的反思只标记为素材候选；后续由「素材」skill 转成 `materials/` 卡片。
- 共享项目/公司 context 不写入 `working-os/projects`；写入 `/opt/processes/context_platform`，并默认使用英文。
- 晋升到 `assets/mental-models.md` 由「系统复盘」负责，收工时不做晋升判断。
