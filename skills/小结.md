# skill: 小结 —— 任务后 3 分钟轻量捕获

**触发**：
- 「小结」→ 对刚完成的任务做 3 分钟记录。
- 「小结 <任务/项目>」→ 对指定任务或项目做 3 分钟记录。
- 「任务小结」→ 同上。

**目的**：忙的时候也能低摩擦捕获任务结果、后续事项和少量可复用反思。`小结` 不是完整复盘，不追求漂亮；它先减轻脑负担，再给「收工」和「系统复盘」提供原料。

## 先读
1. `AGENTS.md`（确认目录边界和 shared context 路由）。
2. 当天 `worklog/<YYYY-MM-DD>-daily.md`（如果存在）。
3. 如果小结明显涉及项目事实、决策、坑、workflow 或 guideline，读对应的 `/opt/processes/context_platform` index；共享 context 仍写入 context repo，不写入 working-os。
4. 只有当本次出现可复用方法、坑、偏好或认知时，才读 `reviews/recurring.md`。

## 流程
1. 用当前对话、最近任务结果或主人提供的材料，提取最小事实：做了什么、产出了什么、还有什么要跟进。
2. 追加到当天滚动日志 `worklog/<YYYY-MM-DD>-daily.md`；不要默认为每个任务新建单独文件。
3. 默认只写四块：`Task`、`Output`、`Follow-ups`、`Reflection Candidate`。
4. `Reflection Candidate` 可以为空。只有当存在可复用方法、坑、偏好或认知时，才把它同步进 `reviews/recurring.md`。
5. 如果某条反思明显适合讲给别人听，可标记 `sharing_material: yes` 或 `maybe`，并写一句 `possible_sharing_use`；不要直接把每条 reflection 都转成素材卡。
6. 如果发现应进入团队/项目共享 context 的事实，按「摄取」规则路由到 `/opt/processes/context_platform`；不确定就留在 follow-up 里问主人。

## daily entry 格式

追加到 `worklog/<YYYY-MM-DD>-daily.md`：

```md
## <HH:MM> · <task/project short name>

### Task
- ...

### Output
- ...

### Follow-ups
- ...

### Reflection Candidate
- type:
  statement:
  evidence:
  context:
  sharing_material: yes / no / maybe
  possible_sharing_use:
```

如果没有 reflection，保留标题并写：

```md
### Reflection Candidate
- None.
```

## recurring 更新规则

- 有 reflection candidate → 和 `reviews/recurring.md` 语义匹配。
- 匹配到 → 追加 instance（日期 + 原话），count +1，更新 last_seen 和 contexts。
- 没匹配到 → 新增条目，count = 1，status = 候选。
- 如果有 `sharing_material` 和 `possible_sharing_use`，同步到 recurring 条目的可选字段。
- 没有 reflection candidate → 不更新 recurring，避免噪音。

## 原则

- 小结控制在 3 分钟内；宁可短，也不要因为追求完整而放弃捕获。
- 小结默认是个人材料，写入 `working-os/worklog`。
- 反思默认先进入 `reviews/recurring.md`；只有明确有表达价值时，后续才经「素材」转成 `materials/` 卡片。
- 共享项目/company context 仍写入 `/opt/processes/context_platform`，并默认使用英文。
- 不自动生成小结；只有主人明确触发 `小结` 或 `任务小结` 时才写。
