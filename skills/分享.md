# skill: 分享 —— 整理和修改已有想法或草稿

**触发**：主人为工作分享、演示或讲稿提供想法、要点或草稿，希望整理思路、调整结构、精炼表达或修改文字。任务中为同事或 stakeholder 准备日常沟通，走 `skills/理解.md`。

**目的**：以主人的观点和表达意图为起点，帮忙说得更清楚、更顺畅；不替主人决定论点，也不凭空补充事实或例子。

## 先读
1. 先看主人提供的想法或草稿及具体修改要求；仅在需要核对事实或寻找已提到的例子时，读取相关 `tasks/<project>/` 笔记、已有分享稿或共享项目 context，确认材料适合目标听众。
2. 若受众、目的或修改幅度会影响输出，先确认这些关键信息；已有明确要求时直接动手，不把采访或主题地图设为前置步骤。

## 流程
1. 从原稿识别主人已经确定的观点、想保留的表达和仍未想清楚的部分；区分结构问题、论证缺口与语言问题。
2. 只有零散想法时，先按主人的方向组织成一条清晰主线；有草稿时直接修改草稿。按请求做润色、删减、重排或重构，保留原意和个人语气；结构改变较大时简要说明取舍，必要时先确认新主线。
3. 给出一份可直接使用的修改稿，并简短指出需要主人确认的事实、空缺或改变了的重点。不默认生成多个版本、主题地图、outline 或讲稿；主人明确要求时再提供。
4. 若主人提供修订反馈，继续在同一稿上迭代。仅在主人要求保存时将稿件放到 `sharing/`；需要保留可复用表达偏好时，也先征得主人同意。

## 边界
- 中文想法可整理为英文分享稿，但不得新增未经确认的观点、数据、引用或项目例子。
- 分享稿是表达产物，不是团队项目事实；外部反馈经核实、有共享价值时才按共享仓库规则提炼。日常任务沟通准备仍属于理解。
