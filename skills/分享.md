# skill: 分享 —— 从素材组织主题地图，再写 outline / talk track

**触发**：
- 「分享 <主题>」+ 想法/要点 → 先生成主题地图，再按主人确认的方向写 outline / talk track。
- 「分享 收」+ 主人改过的稿 → 学习主人的分享风格。

**目的**：帮主人把长期素材、项目经验和临时想法组织成深入分享。默认不要太早写成稿；先把主题地图、论点、例子和缺口摆出来，再进入 outline 或 talk track。

## 先读
1. `style/sharing-profile.md` —— 主人已沉淀的分享风格规则。
2. `materials/index.md` —— 可复用个人素材卡入口。
3. 如果分享涉及具体项目，读 `/opt/processes/context_platform/projects/<project>/index.md` 和相关 shared context。

## 流程 A：主题地图
1. 读分享主题、主人提供的想法、`materials/index.md` 中相关素材卡，以及必要的项目 shared context。
2. 先产出主题地图，默认存到 `sharing/<YYYY-MM-DD>-<topic>-theme-map.md`。
3. 主题地图包含：
   - 核心问题：这次分享到底要回答什么。
   - 可能主线：1-3 条可选故事线。
   - 关键论点：每条主线下的主要观点。
   - 可用素材卡：引用 `materials/cards/<id>.md`。
   - 真实项目例子：来自 worklog、context_platform 或主人输入。
   - 还缺什么：需要补的例子、数据、图、代码 walkthrough 或听众背景。
4. 主题地图完成后，先让主人确认方向；除非主人明确要求，不直接写完整讲稿。

## 流程 B：outline / talk track
1. 主人确认主题地图后，读 `sharing-profile.md`，套用已知风格（结构习惯、开场方式、例子密度、详略偏好等）。
2. 产出 outline、talk track 或 presentation brief。分享稿本身优先是 talk track；不要默认附多个版本。
3. 如果是英文分享，可把中文素材转成自然英文表达，但不要增加素材没有支撑的新观点。
4. 提示主人：改完用「分享 收」喂回，我来学。

## 流程 C：分享 收（学风格）
1. 对比 [我的初稿 v0] vs [主人的最终稿 v1]，提炼差异 → **规则化**追加进 `sharing-profile.md`。
2. 配对存 `style/sharing-samples/<日期>-<简述>.md`。

## 分享后的回流（三个门，防回声室）
系统自己的产出不自动变成自己的输入，只有外部世界的反馈才自动回流：
1. **分享稿本身** → **不**回灌项目 context；只通过 v0/v1 diff 喂 `sharing-profile.md`（风格）。
2. **外部反馈**（同事提问、哪里卡住、会后追问）→ 真新信号，走「**摄取**」进对应项目 context。
3. **你讲透的好解释** → 由主人**手动晋升**进 `materials/`、`worklog/` 或项目 context，不自动。

> 原则：系统产出要回流，得主人主动按「晋升」；外部反馈才自动进。润色线同理。
