# skill: 分享 —— 从工作经验组织主题地图和讲稿

**触发**：
- 「分享 <主题>」+ 想法/要点 → 先生成主题地图，再按主人确认的方向写 outline / talk track。
- 「分享 收」+ 主人改过的稿 → 学习主人的分享风格。

**目的**：帮主人把当前想法、项目经验和已有记录组织成工作分享。默认先明确受众、论点、例子和缺口，再进入 outline 或 talk track；若主人已经明确要求成稿，直接写稿。

## 先读
1. `style/sharing-profile.md`；英文稿按需读 `style/english-profile.md`。样本仅在需要对照时读取。
2. 主人提供的想法、相关 `judgments.md` 条目和本地 `worklog/` 或已有 `sharing/` 产物；只读与主题有关的部分。
3. 如果分享涉及具体项目，读 `/opt/processes/context_platform/projects/<project>/index.md` 和相关 shared context，并核对是否适合对目标听众披露。

## 流程 A：主题地图
1. 确认听众、目的和分享主题，收集主人提供的要点、相关个人判断、工作记录及必要的项目 shared context。
2. 先产出主题地图，默认存到 `sharing/<YYYY-MM-DD>-<topic>-theme-map.md`。
3. 主题地图包含：
   - 核心问题：这次分享到底要回答什么。
   - 可能主线：1-3 条可选故事线。
   - 关键论点：每条主线下的主要观点。
   - 可用证据与例子：注明来自用户输入、worklog 或共享项目 context。
   - 真实项目例子：来自 worklog、context_platform 或主人输入。
   - 还缺什么：需要补的例子、数据、图、代码 walkthrough 或听众背景。
4. 主题地图完成后，先让主人确认方向；除非主人明确要求，不直接写完整讲稿。

## 流程 B：outline / talk track
1. 主人确认主题地图后，读 `sharing-profile.md`，套用已知风格（结构习惯、开场方式、例子密度、详略偏好等）。
2. 产出 outline、talk track 或 presentation brief。分享稿本身优先是 talk track；不要默认附多个版本。
3. 如果是英文分享，可把中文要点转成自然英文表达，但不要增加没有证据的新观点。
4. 主人提供修改后的稿件且要求更新风格时，再对比初稿与最终稿并维护风格规则或样本。

## 风格更新（按需）
主人明确要求时，对比初稿与最终稿，提炼可复用的差异，更新 `style/sharing-profile.md`；有必要保留对照时，再存入 `style/sharing-samples/`。

> 原则：分享稿不是新的项目事实；外部反馈需要核对后才写入共享 context，个人判断仅在主人要求时记录。
