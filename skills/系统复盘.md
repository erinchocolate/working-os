# skill: 系统复盘 —— 定期把「复盘」对准 working-os 本身

**触发**：
- 「系统复盘」→ 对本系统做一次复盘。
- 「系统复盘 <日期>」→ 复盘指定周期。
- 双周或月度提醒出现后，主人说「系统复盘」。

**目的**：循环 A/B 是用系统干活；本 skill 是用系统改系统。定期把摩擦点变成对 `AGENTS.md`、`skills/` 和目录约定的真实改动，并把认知候选分流到行动原则或表达素材。

## 先读
1. `AGENTS.md` —— 系统现状与约定。
2. `skills/` 目录列表 —— 有哪些工作流可被改。
3. 上一轮系统复盘以来的 `worklog/`、`reviews/recurring.md`、`reviews/system/`。
4. 最近执行 worklog 是否有 `Reflections`，以及这些 reflection 是否已同步进 `reviews/recurring.md`。
5. `assets/INDEX.md`、`materials/index.md` 和 `/opt/processes/context_platform` 中近期相关共享 context 的变化。

## 流程一：量飞轮（先诊断，别凭感觉）
统计这一周期的客观信号：
- `worklog/` 新增几篇？执行后是否真有记录？
- 新增 daily 小结有几条？哪些有 `Reflection Candidate`？哪些已经进入 `reviews/recurring.md`？
- 新增 thinking entries 有几条？哪些有 `recurring_candidate`、`material_candidate` 或 `shared_context_candidate`？哪些已经完成分流？
- 新增 worklog 里有几篇包含 `Reflections`？其中几条已进入 `reviews/recurring.md`？
- `assets/` 新晋升几条？候选池 `recurring.md` 涨了多少？
- `materials/` 新增几张素材卡？哪些来自 worklog、recurring、学习笔记或 assets？
- recurring 中有多少 `sharing_material: yes / maybe` 还没有转成素材卡？
- 共享项目/公司 context 是否正确路由到了 `/opt/processes/context_platform`？
- `working-os` 是否仍混入了应属于 context_platform 的项目/公司 context？
- 关键词（摄取/执行/小结/思考/收工/系统复盘/润色/分享/学习）哪些用过、哪些一次没碰？
- `小结` 是否真的减轻脑负担，还是变成新的填写负担？
- `思考` 是否真的帮助主人把未成形想法讲深，还是变成新的记录负担？

一句话判断当前阶段：
- **播种期**：`assets/` 仍接近空、context 薄 → 下周期继续偏向「摄取 + 小结 + 收工」。
- **杠杆期**：`assets/` 已有 ≥3 条晋升资产且加载真能抄近路 → 可以多用执行/分享，本 skill 重心转向调优。

## 流程二：三问（核心）
1. 这周期哪一次，加载 context/assets 真的省了时间？
2. 这周期哪一次，用 skill 反而比直接干还累？
3. 这周期有没有一条认知、会议信号或 agent session，系统没接住？

## 流程三：双晋升判断
对 `reviews/recurring.md` 和 thinking worklog 中的候选做两种不同判断：

1. **行动原则晋升**：跨情境、反复验证、能指导主人未来怎么工作 → 提名进入 `assets/mental-models.md`，仍需主人确认。
2. **materials 晋升**：适合讲清一个主题、能支持 AI / Marvin / Hype Stack 等深度分享 → 提名为「可转素材卡候选」，后续由「素材」skill 生成 `materials/cards/`。

同一条认知可以同时进入两条路径：作为行动原则进入 `assets/mental-models.md`，作为表达素材进入 `materials/`。

## 流程四：改系统
针对摩擦点：
1. 定位是哪份 `skills/*.md`、`AGENTS.md` 或目录约定造成的别扭。
2. 提出具体改动（删一步、改触发、调先读顺序、加一条原则、改提醒时间等）。
3. 停下来问主人：接受 / 改写 / 否决。确认后才改文件。
4. 改完在系统复盘记录里写清「改了什么 + 为什么」。

## 流程五：记账
写 `reviews/system/<日期>.md`：
```
- 阶段: 播种期 / 杠杆期
- 飞轮信号: daily 小结 N 条 / thinking entries N 条 / Reflections N 条 / recurring 增量 / assets 新晋升 M 条 / materials 新增 K 张 / shared context 路由情况
- 省时刻: 哪次加载帮了忙
- 行动原则候选: 哪些 recurring / worklog / thinking / 学习笔记值得晋升到 assets/mental-models.md
- 可转素材卡候选: 哪些 recurring / worklog / thinking / 学习笔记值得转入 materials
- 摩擦点: 哪次别扭 → 改了哪份 skill / 为什么
- 下周期偏向: 一句话
```

## 边界
- 本 skill 可以改 `AGENTS.md`、`skills/` 和目录约定。
- 不直接改项目事实；项目事实由「摄取/执行」写入 `context_platform`。
- `assets/mental-models.md` 是唯一行动原则文件，晋升前需要主人确认；`materials/` 是表达素材，可由「素材」skill 从已确认来源生成。
