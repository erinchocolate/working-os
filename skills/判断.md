# skill: 判断 —— 口述后保存个人判断或技术学习

**触发**：主人明确表示要记录一个技术学习、工作判断或取舍。普通讨论和执行任务不自动存档。

## 先读

1. `judgments.md` 中的相关条目，避免同义重复。
2. 如果判断依赖某个项目，按需读 `/opt/processes/context_platform/projects/<project>/index.md`、相关共享决定和真实代码；需要证据时再查本地 `worklog/`。

## 流程

1. 听完口述，先用简短语言复述判断及使用场景；必要时追问支持证据、反例、限制和下一次如何验证，不把假设写成结论。
2. 区分个人可复用判断和团队正式项目决策。后者以共享 context 为真源，遵循共享仓库的阅读、索引、英文和 review 规则；个人库可以留简短方法和链接，但不复制项目事实。
3. 提出准备保存的文字，向主人确认或接受修订。确认后在 `judgments.md` 中更新已有判断或追加短条目，写清判断、适用边界、依据、状态和绝对日期；未验证的学习明确标记待验证。
4. 告诉主人保存位置和仍待确认之处。若只是讨论想法，没有明确要求保存，就停在对话，不建文件。

## 边界

- 不要求一个判断多次出现才可记录，也不维护候选池、素材卡或晋升门槛。
- 不把原始长段口述、敏感项目数据或未经确认的推断写入个人库。
- 技术学习可记为观察或工作假设；证据变化时修改原条目并注明边界，不盲目叠加新条目。
