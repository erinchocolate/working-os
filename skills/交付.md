# skill: 交付 —— 将已确定的方案实现、验证并上线

**触发**：方案和验收标准已明确，需要写代码、测试、审阅、部署或检查上线结果。方案尚未确定或验证暴露新问题时，走 `skills/理解.md`。

**目的**：基于共享 context 和真实代码完成从方案到上线验证的闭环；不把一次代码修改或一次测试当作交付完成。

## 先读
1. `/opt/processes/context_platform/README.md`、`AGENTS.md` 和相关项目或共享区域的 index；按需读发布、测试、已知风险等文档。
2. 按交付所属项目选择资料：Marvin 项目交付先读 `/opt/processes/context_platform/projects/marvin/delivery/index.md`，再按任务读相应文档。
	代码、测试或审阅时读 Marvin 的 `testing/test-selection-checklist.md`；准备 PR 时读 `guidelines/precommit.md`；Explore 部署时读 `testing/databricks-smoke-checklist.md`。
	其他项目交付则从各自项目的 index 选择交付、测试和发布资料，不套用 Marvin 的清单，也不默认全读。
3. 真实代码、配置、测试和部署路径；共享 context 只提供背景，不替代实现仓库。
4. 如有 `tasks/<project>/` 下的任务笔记，确认已选方案、验收标准、证据与未决风险；没有则不强制创建。

## 流程
1. 确认交付范围、验收标准、相关环境、权限与回退条件；未定的设计问题先转 `skills/理解.md`。
2. 实现方案并运行针对性测试；按变更风险补充集成或实际环境验证，记录哪些检查通过、失败或尚未执行。
3. 请求另一位可用的 agent 独立审阅代码、测试和行为风险；处理发现并复查改动。若无法完成独立审阅，明确说明缺口，不声称已审阅。
4. 在发布前核对最终变更、验收结果、部署目标和回退准备；生产部署必须取得明确授权，不以完成测试或审阅代替授权。
5. 获授权后部署并核对实际版本、关键行为和运行状态；出现异常时按已确认的回退或处置路径处理，说明上线结果与残余风险。
6. 如有任务笔记，在同一份笔记更新交付状态、验证与审阅结果、部署结果和待办。新的团队可复用结论按共享仓库规则独立提炼、更新相关 index 并请相关人员审阅；不复制代码或个人笔记。

## 原则
- 测试、审阅和发布验证可以迭代；只执行其中一步不等于完成交付。
- 未经授权不直接上线；不能执行的检查与未解决的风险应明确交接。
- 项目正式决定以共享 context 为准；个人任务笔记不是团队决定。
