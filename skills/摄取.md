# skill: 摄取 —— 把输入路由到共享 context 或个人认知管道

**触发**：
- 「摄取 <项目名>」+ 粘贴内容 → 直接摄取到指定项目的共享 context。
- 「摄取 <项目名> <文件路径>」→ 摄取指定文件。
- 「摄取」+ 粘贴内容 → AI 判断归属，不确定就问。

**目的**：主人只负责捕获，不负责整理；AI 判断内容应该进入
`/opt/processes/context_platform` 的共享项目/公司 context，还是进入
`working-os` 的个人 worklog/reflection。

## 先读
1. 常驻指针：`assets/INDEX.md`、`style/*-profile.md`（了解主人）。
2. `/opt/processes/context_platform/README.md` 和
   `/opt/processes/context_platform/AGENTS.md`（确认共享 context 边界）。
3. 若已确定目标项目，读
   `/opt/processes/context_platform/projects/<project>/index.md`，再按该
   index 读取相关 design、workflow、decision、pitfall 或 feedback 文档。
4. 若是公司级 guideline，读
   `/opt/processes/context_platform/company_guidelines/index.md`。

## 路由规则

| 信息类型 | 目标 |
|---|---|
| 项目事实、当前状态、设计原因、决策、坑、workflow、用户反馈、实验记录 | `/opt/processes/context_platform` |
| 公司/团队 guideline、共享操作说明、可被同事复用的 reference | `/opt/processes/context_platform` |
| 个人学习、反思、工作方法、临时想法 | `working-os/worklog` 和 `reviews/recurring.md` |
| 表达偏好 | `style/` |
| 分享稿、presentation brief、talk track | `working-os/sharing/` |

如果同一件事同时有项目价值和个人价值，拆成两份：

- 共享事实 → `context_platform`
- 个人反思 → `working-os/worklog` 和 `reviews/recurring.md`
- 行动原则 → 不由摄取直接写入 `assets/`；先进入 recurring，系统复盘确认后再晋升到 `assets/mental-models.md`

## 流程
1. **定归属**：判断是共享 context、个人认知、还是两者都需要。
2. **读目标 index**：共享内容必须先读目标目录的 `index.md` 或 README。
3. **翻译与脱敏**：写入 `context_platform` 的内容默认用英文；中文输入先翻译成英文。不要写入 credentials、PII、raw private meeting dumps 或敏感生产样例。
4. **抽取并路由**：只沉淀 durable context，不复制实现代码，不转存长原文。
5. **调和已有内容**：新增、更新、跳过重复；遇到矛盾时问主人。
6. **回报**：说明写入了哪里、更新了哪些 context、哪些信息仍需确认。

## 调和规则
- **新增**：全新信息 → 加入。
- **更新**：已有条目变了 → 改写并标变更日期。
- **矛盾**：与旧的冲突 → 当场问主人；确认后把旧内容标明 superseded 或追加新决策。
- **重复**：已有 → 跳过。

## 人机边界
- 自动：分类、翻译、归档、抽取、路由、新增、更新、跳过重复。
- 当场问：归属不确定、metadata 不确定、敏感度不确定、与旧 context 矛盾。
